## 1. Objective

One question: **how much does realistic transaction cost remove from the raw
Turtle baseline, and at what round-trip cost does its edge disappear?**

EXP-001 measured only two fee points (0.05% and 0.20%). This experiment completes
the cost analysis by adding the mid level, per-year cost runs, explicit turnover
and fees-paid totals, and the fee level at which the strategy stops working —
which is the honest way to express "slippage headroom".

## 2. Hypothesis under test

> The Turtle breakout edge is cost-sensitive: because the strategy pays a round
> trip on roughly every trade it takes, a fee increase of 0.05 percentage points
> per side removes a measurable share of per-trade expectancy, and beyond some
> fee level the full-sample profit factor falls below 1.00.

This is the "cost sensitivity" failure mode recorded in
`research/hypotheses/turtle.md` §7. It is falsifiable: if the strategy is
insensitive to fees, profit factor will stay materially above 1.00 across the
whole sweep.

## 3. Frozen implementation

**No strategy logic changes.** `user_data/strategies/turtle/DonchianTurtleBaseline.py`
and the `user_data/strategies/shared/` signal, indicator and risk modules are
byte-identical to the EXP-001 baseline commit
`12acbf7017a04418dbfa54771edf5c97b358d618`. This experiment must not edit them.

| Element | Specification (identical to EXP-001) |
|---------|--------------------------------------|
| Timeframe | 4h |
| Entry | `close[t] > max(high[t-20:t])`, rising edge only, ATR defined |
| Exit | `close[t] < min(low[t-10:t])`, or fixed `2 × ATR(20 at entry)` stop, or −30% backstop |
| Sizing | `equity × 0.01 / stop_distance × price`, capped at equity |
| Direction | long only (spot), no leverage, no pyramiding |
| ROI | disabled |
| Max open trades | 5 |

Only the transaction-cost input changes between runs. The cost input is supplied
by the framework (`--fee`), not by the strategy, so the strategy code is
untouched by design.

## 4. Fixed parameters

`entry_period=20`, `exit_period=10`, `atr_period=20`, `atr_stop_multiple=2.0`,
`risk_per_trade=0.01`, `timeframe="4h"`.

**None of these may be tuned in EXP-002.** Any tuning would destroy this
experiment's only valid interpretation (a cost measurement on the frozen
baseline).

## 5. Dataset

Identical to EXP-001 and to `research/preregistration/experiment_protocol.md`.
No deviation.

- 10 Binance spot pairs: BTC, ETH, BNB, SOL, XRP, ADA, DOGE, LINK, AVAX, DOT (USDT)
- 4h candles
- Full sample 2019-01-01 → 2026-01-01

- Per-year: each calendar year 2019 … 2025
- Raw candles git-ignored, reproducible with `user_data/scripts/download_data.ps1`

## 6. Cost scenarios

Freqtrade has no native slippage model, so slippage is represented as additional
per-side transaction cost, exactly as the protocol prescribes. Fee scenarios:

| Scenario | Fee per side | Interpretation |
|----------|--------------|----------------|
| base | 0.05% | taker only |
| mid | 0.10% | taker + ~0.05% slippage |
| stress | 0.20% | taker + ~0.15% slippage |
| bracket-1 | 0.30% | heavy slippage / thin book |
| bracket-2 | 0.50% | severe |
| bracket-3 | 1.00% | extreme (edge-loss bracket) |

The brackets exist solely to locate the fee level at which the edge disappears;
they are diagnostics, not promotion criteria.

## 7. Runs to perform

Frozen before execution. 30 backtest runs, no discretionary additions.

| Group | Timerange | Fee levels |
|-------|-----------|------------|
| Full sample | `20190101-20260101` | 0.05%, 0.10%, 0.20%, 0.30%, 0.50%, 1.00% (6 runs) |
| OOS holdout | `20250101-20260101` | 0.05%, 0.10%, 0.20% (3 runs) |
| Per year | `YYYY0101-YYYY+10101`, 2019 … 2025 | 0.05%, 0.10%, 0.20% (21 runs) |

Per-year runs each start from 10,000 USDT, matching EXP-001, so per-year figures
are directly comparable.

**OOS evaluation accounting (charter §15).** The strategy version is identical to
EXP-001, so the holdout was already evaluated once for this version. The 0.05%
holdout run here is a *reproduction check* of EXP-001; the 0.10% and 0.20%
holdout runs are *cost views* of the same version. No parameter, threshold or
decision is selected from any holdout number in this experiment, so this is not
holdout optimisation. Recorded count: 1 selection-relevant OOS evaluation
(EXP-001) + 3 non-selection cost views (this experiment).

## 8. Success criteria

Charter criteria A1–A8, all reported criterion-by-criterion regardless of
outcome. A1 and A6 are properties of the strategy, not of the fee level; they are
measured on the full-sample base-cost run. A4/A5 use the OOS holdout at base
cost. M1 is experiment-specific and is pre-registered here:

| # | Criterion | Threshold |
|---|-----------|-----------|
| A1 | Trades (full sample, base) | >= 200 |
| A2 | Profit factor, full sample, 0.05% | >= 1.10 |
| A3 | Per-trade expectancy p-value, full sample, 0.05% | < 0.05 |
| A4 | OOS net return, 0.05% | >= 0 |
| A5 | OOS profit factor, 0.05% | >= 1.00 |
| A6 | Wallet max drawdown, full sample, 0.05% | < 35% |
| A7 | Profitable calendar years @ 0.05% | >= 60% |
| A8 | Profit factor, full sample, 0.20% | >= 1.05 |
| **M1** | **Profit factor, full sample, 0.10% (mid)** | **>= 1.10** |

Diagnostics that are reported but are not pass/fail criteria: fees paid in USDT,
turnover, fee drag as a share of gross profit, and the interpolated round-trip
fee at which full-sample profit factor crosses 1.00.

## 9. Out of scope

Strategy-logic changes, filters, indicator additions, parameter optimisation,
position-sizing changes, shorting, leverage, pyramiding, ML, portfolio routing,
Pullback or any other strategy implementation, and re-running the OOS window
under changed settings. If the cost result is poor, it is **documented, not
fixed**.

## 10. Expected failure modes

From `research/hypotheses/turtle.md` §7, the modes this experiment can confirm or
refute:

| Mode | What this experiment would show |
|------|-------------------------------|
| Cost sensitivity | Profit factor falls monotonically as the fee rises |
| Edge loss | A fee level exists above which full-sample PF < 1.00 |
| Regime dependence | Per-year cost drag concentrated in high-turnover / low-edge years |
| Effective sample size | Fees scale with trade count, so cost drag is largest where trades are most numerous |

All else being equal, the expected shape is a monotone decline in profit factor
and a monotone increase in fee drag as the fee rises. A non-monotone result would
itself be a finding worth recording.
